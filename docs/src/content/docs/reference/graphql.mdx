`POST /graphql`, served by `GraphqlController`. `/graphiql` is mounted in development.

`app/graphql/`

## The schema

```ruby
class UrisSchema < GraphQL::Schema
  query(Types::QueryType)
  mutation(Types::MutationType)
  subscription(Types::SubscriptionType)

  use GraphQL::Subscriptions::ActionCableSubscriptions
  use GraphQL::Dataloader

  max_depth(15)
  max_query_string_tokens(5000)
  validate_max_errors(100)
end
```

### Queries

| Field | Grant | |
| --- | --- | --- |
| `tenant` | `uris:catalog:read` | who answered |
| `item(id:)` | `uris:catalog:read` | one item |
| `items(kind:, resourceId:, feed:, after:, limit:)` | `uris:catalog:read` | a page of the catalog |
| `search(query:, kind:, after:, limit:)` | `uris:catalog:read` | a page of the index, with a `total` |
| `kinds` | `uris:catalog:read` | counts grouped by kind |
| `resources(archived:)` | `uris:resources:read` | in use by default, put away on request |
| `resourceTypes` | `uris:resources:read` | every type that can be attached, and what each needs |
| `feeds` `feed(slug:)` | `uris:catalog:read` | feeds, newest first |
| `settings` | `uris:settings:read` | every setting the grant may read |
| `run(id:)` | `uris:catalog:read` | one run |
| `runs(kind:, status:, feedId:, itemId:, after:, limit:)` | `uris:catalog:read` | a page of runs |
| `mergeProposals(status:, after:, limit:)` | `uris:catalog:read` | open proposals by default |
| `auditEvents(action:, status:, subject:, after:, limit:)` | `uris:catalog:read` | a page of the audit log |

Paged fields go through `Page.of(scope, after:, limit:)` — keyset pagination on the primary key,
newest first, `limit` clamped to 1–200 with a default of 50. One extra row is fetched to answer
"is there more"; nothing counts, so `total` is null.

`search` is the exception. The engine orders by score, so "everything after this id" is not a
place in the results — it walks by offset through `Page.at(nodes, from:, total:)`, `after` is how
far in to start rather than an id, and the engine's own hit count fills `total`. It is the one
paged field that can tell you how many matched rather than only whether more remain.

### Mutations

| Field | Grant |
| --- | --- |
| `addNote` `snapshotUrl` `fetchUrl` | `uris:catalog:write` |
| `analyzeItem` `mergeItems` `splitReference` `proposeMerges` `settleMergeProposal` | `uris:catalog:write` |
| `renameItem` `noteItem` `forgetItem` | `uris:catalog:write` |
| `exportItems` `cancelRun` | `uris:catalog:write` |
| `saveFeed` `runFeed` `pauseFeed` `deleteFeed` | `uris:catalog:write` |
| `attachResource` `enrollResource` `syncResource` `checkResource` `archiveResource` | `uris:resources:command` |
| `setDefaultStorage` `setDefaultInference` `setSyncInterval` | `uris:resources:command` |
| `setSetting` | `uris:settings:write` |

`exportItems` and `cancelRun` take `uris:catalog:write` here and `uris:resources:command` over
[MCP](/reference/tools/). Merging and dedupe are reachable here and nowhere else, and so is
attaching a resource by typing its credential — MCP only ever hands back an enrollment link,
because a secret in a tool call is a secret in the transcript.

`addNote` answers with the item. `snapshotUrl` and `fetchUrl` answer with a `Run` to watch, since
rendering a page and pulling a file both outlast a request.

`noteItem` writes your own words onto an item and clears them when given a blank. A note is
indexed alongside the title and weighted the same, so it is a way of making something findable by
what you call it rather than by what is in it — and `Item#merge!` carries a note across before the
emptied item is destroyed, because otherwise merging would quietly eat it.

Nothing that removes reaches through to storage anyone else owns. `forgetItem` drops an item's
references and its search entry, and a later sync of the same resource will catalogue it again.
`deleteFeed` takes the prompt and its runs; the items it minted are nullified rather than
destroyed, and the payload says how many outlived it. `archiveResource` sets and unsets
`archived_at`, which is what `Resource.active` reads — so an archived resource stops being offered
to tools and jobs while everything it catalogued stays searchable. All three are audited.

### Subscriptions

`itemAnalyzed`, triggered by `Item#announce_analyzed!` both globally and per item id.
`Subscriptions::BaseSubscription` declares `subscription_scope :tenant_id`.

## Authorization is the same Grant

`Types::BaseField` takes a `grants:` option and checks it in `authorized?`:

```ruby
field :resources, [ Types::ResourceType ], null: false, grants: "uris:resources:read"
```

A field whose grant the token does not carry raises a `GraphQL::ExecutionError` naming the missing
scope. A field with no `grants:` is open to any authenticated caller.

Both interfaces reach `Grant` through the `Granted` concern. The browser's token lives in the
encrypted session and is verified on the way in exactly as a presented bearer would be — see
[Drive it from Claude](/guides/connector/).

## The Ruby schema is the source of truth

The TypeScript is generated from it and is not committed:

```sh
bin/rails graphql:dump_schema   # writes web/schema.graphql
npm run codegen                 # regenerates the TypeScript
```

`bin/dev` runs both watchers (`Procfile.dev`, the `schema` and `codegen` processes). CI runs the
same two commands before the typecheck, because `web/schema.graphql` and the generated types are build
products — a clean checkout has neither and the Vite build fails without them.

## The client

urql, with `@urql/exchange-graphcache` and Action Cable subscriptions.
