---
title: The four movements
description: sync, analyze, search and export — the four operations everything else serves.
---

```
sync       resource → catalog        pull references in
analyze    content  → understanding  per thing, by kind
search     catalog  → you            one index across everything
export     catalog  → resource       bytes back out
```

All four are reachable over `/mcp` and over `/graphql`.

## sync

`Resource#sync!` claims the resource, starts a `Run`, and enqueues `SyncResourceJob`.

The job iterates `each_page` on the resource and records a `ThingReference` per object. No bytes
move. Six of the nine types implement `each_page`; the rest cannot sync — see
[Resources](/concepts/resources/).

`app/models/resource.rb`, `app/jobs/sync_resource_job.rb` · [Sync a resource](/guides/sync/)

## analyze

`Analyzer.for(thing)` picks the first of twelve analyzers whose `handles?` returns true, then runs
its `step`s. Steps record `started_at`, `finished_at` and either `result` or `error` under
`reference.analysis["steps"]`.

`app/analyzers/` · [Analysis](/concepts/analysis/)

## search

`Thing.search` asks `SearchIndex` for ids and reloads them from Postgres in index order. OpenSearch
is the query path; Postgres is the system of record.

`app/models/search_index.rb` · [Search the catalog](/guides/search/)

## export

`ExportThingsJob` iterates the things a selector matches and copies each one's bytes into a storage
resource, recording the copy as another `ThingReference` on the same thing.

`app/jobs/export_things_job.rb` · [Export things back out](/guides/export/)

## Sync and export are one form

The same shape with source and destination swapped. Cataloguing is a flag, not a destination.

| source | destination | catalogued | is |
| --- | --- | --- | --- |
| a resource | — | ✓ | ingest — references only |
| a resource | a storage resource | — | backup |
| a resource | default storage | ✓ | ingest + materialize |
| things matching a selector | a storage resource | — | export |
