title: Items
description: One item row, one reference per place the bytes live, and the kind that decides how it is analyzed.
---

An item is a row in `items` with one `item_references` row per place its bytes live. The bytes
themselves stay in the resource they came from.

`app/models/item.rb` · `app/models/reference.rb`

## Item

| | |
| --- | --- |
| `kind` | what it is — `pdf`, `email`, `image`… Required |
| `title` | display name, usually the basename of the locator key |
| `parent_id` | set on an item extracted from another, such as an email attachment |

`Item#analyzed_at` is the maximum `analyzed_at` across its references, not a column.

## Reference

| | |
| --- | --- |
| `resource_id` | which resource holds this copy |
| `locator_key` | the key within it — unique per `(tenant_id, resource_id)` |
| `locator` | the type-specific address, as JSON |
| `version` | what the resource last reported, usually an ETag |
| `changed_at` | set when `version` changes, which also clears `analyzed_at` |
| `analysis` | the step machine's record — see [Analysis](/concepts/analysis/) |

`Reference.discover!` is the sync path: it finds or creates the reference, creates an item if
there is not one yet, and calls `note_version!`. A changed version re-opens analysis.

`Reference.record!` is the export path: it attaches a reference to an item you already have,
and records `source_version` so `stale_against?` can tell whether the copy has fallen behind.

## Kind

Assigned from the file extension by `Kind.for_filename` (`app/models/kind.rb`), defaulting to
`file`.

| kind | extensions |
| --- | --- |
| `pdf` | pdf |
| `image` | png, jpg, jpeg, gif, webp, heic, tif, tiff |
| `text` | txt, md, rtf |
| `data` | csv, tsv, json, xml |
| `xlsx` | xlsx, xls, ods |
| `doc` | doc, docx, odt |
| `audio` | mp3, m4a, m4b, wav, flac, ogg, oga, opus, aac, wma, aiff, aif |
| `video` | mp4, m4v, mov, mkv, webm, avi, wmv, mpg, mpeg |
| `calendar` | ics |
| `contact` | vcf, vcard |
| `pkpass` | pkpass |
| `email` | eml |
| `file` | anything else |

Two kinds never come from a filename, because the things they name do not have one. A resource
that knows what it found overrides `kind_for` and says so directly:

| kind | assigned by |
| --- | --- |
| `feed` | `Resource::Rss` — an entry in a feed, keyed on its guid |
| `page` | `Resource::Web` — a snapshot, keyed on the address it was taken from |

Kind is not resource type. `pdf` is a kind; `s3` is a [type](/concepts/resources/).

## Getting in

Every path that turns bytes into an item goes through `Intake.write!` (`app/models/intake.rb`):
sanitise the key, write to the tenant's default storage, `Reference.discover!`, queue analysis.
There is one place that does it rather than one per caller.

| From | Path | Lands as |
| --- | --- | --- |
| a dropped or chosen file | `POST /uploads` | whatever `Kind.for_filename` says |
| a typed or pasted note | `addNote` | `text`, under `notes/` |
| the file at an address | `fetchUrl` → `FetchUrlJob` → `Download` | named by what was served, under `downloads/` |
| a page as it looks now | `snapshotUrl` → `SnapshotUrlJob` → `Resource::Web#snapshot!` | `page`, keyed on the address |
| a connected resource | `SyncResourceJob` | whatever `kind_for` says |
| an attachment inside an email | `Analyzer::Base#extract_children!` | a child item, see below |

`snapshotUrl` and `fetchUrl` open a `Run` each — rendering and downloading both take long enough
that the caller watches rather than waits.

`Download` re-checks every hop against `PublicAddress` rather than only the address it was handed:
a public host answering with a redirect to `169.254.169.254` is the attack that a single check
misses. It refuses a scheme outside `http` whatever `URIS_ALLOW_PRIVATE_FETCH` allows, caps the
body while reading it rather than after, and names the file from `Content-Disposition`, then the
path, then the content type — so analysis, which is keyed off the extension, knows what it has.

## Children

An analyzer that declares `has_children?` returns child bodies from `children_of`, and
`Analyzer::Base` writes them into a `Resource::Database` resource keyed `children` before analyzing
the parent. `Item::DEPTH` caps the chain at 4.

`Item#body_text` is the union of the strings extracted from an item's own references and its
children's, so an email matches on a word that only appears in an attached PDF.

`Item#children_ready?` is true when every child has an `analyzed_at`. A parent that found children
returns without analyzing; the last child to finish re-enqueues it (`AnalyzeItemJob#wake_parent`).

## Merging

`Item#merge!` moves every reference off another item onto this one.
`Blocking` groups candidates, `ProposeMergesJob` writes `MergeProposal` rows, and the GraphQL
mutations `mergeItems`, `settleMergeProposal` and `splitReference` act on them.

## Deletion

Deleting an item and deleting the bytes it points at are separate operations.

| | Does | Reversible by |
| --- | --- | --- |
| destroy the item | drops the row, its references and its analysis | re-syncing the resource |
| delete the object | removes the bytes from the resource | nothing |

`Item` `dependent: :destroy` cascades to references and children. Nothing in the catalog deletes a
resource's objects.

## Scale

One table, cursor pagination through `Page.of`, OpenSearch as the query path. `count(*)` is avoided
on catalog-sized scopes.
