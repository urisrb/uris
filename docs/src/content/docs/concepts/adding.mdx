---
title: Adding things
description: How a file, a note, a URL or a synced record enters the catalog, and where its bytes end up.
---

There are two ways into the catalog. A file you hand to uris is staged, analyzed and then placed
in a resource. A record a [resource](/concepts/resources/) already holds is referenced where it is
and never moves. Both paths end in an [analysis](/concepts/analysis/).

| Way in | Needs | Lands as |
| --- | --- | --- |
| `POST /uploads` | `uris:catalog:write` | staged file, cause `upload` |
| `addNote` | `uris:catalog:write` | staged `text/markdown` at `notes/<time>-<name>.md` |
| `fetchUrl` | `uris:catalog:write` | staged file at `downloads/<time>-<name>` |
| `snapshotUrl`, or the `resource` tool's `snapshot` | `uris:catalog:write`, or `uris:resources:command` | a page written straight to storage |
| sync | the resource being syncable | references, analyzed once each |

## Staging

`POST /uploads` takes a multipart `file` and an optional `path`. The request answers `202` with the
feed id, type, mime, path and analysis id before any byte reaches a resource. The bytes are held
in Active Storage and nothing else: `Disk` locally, and whatever service `URIS_STAGING_SERVICE`
names in production. The mime comes from the path's extension, not from the content type the client
declared. The request is refused with `422` when:

- no file was sent;
- the path has nothing usable left after cleaning, or is longer than 900 bytes;
- no active store accepts that mime at that size.

A path already stored or already staged lands on the same feed rather than a new one. `addNote`
refuses an empty body or one over a megabyte, and names an untitled note after its first line.

`fetchUrl` checks the address first, and refuses if the tenant has no store at all. It then starts
a `fetch` run, and `FetchUrlJob` downloads the URL. Each redirect is checked again, because a public
host that redirects to `169.254.169.254` is the whole attack. The download follows four redirects
at most, allows five seconds to connect and thirty to read, and fails on any status other than a
success. The ceiling is 100 MB. It is checked against `Content-Length` and again while the body
streams, so a server that lies about the length is still cut off. The file is named from
`Content-Disposition`, or else the URL's last path segment, and gets an extension from the content
type if it has none. The final URL is kept as the file's source and carried onto the stored
reference.

## Placement

`Placement` decides where a staged file ends up. The candidates are the active resources that can
store, accept the file's mime, and have room for its size. The internal `children` and `derived`
stores are never candidates. Placement happens at one of three points in the pass:

1. **`returned!`**, before the analyzer runs. A file already stored at this path goes back to that
   resource, if it still accepts the file. The existing reference gets a `changed_at`, so the
   cached steps are superseded instead of describing the old bytes.
2. **The agent**, when the file is still staged. It is shown the candidates, with the default
   storage marked, and asked to call `feed` with `do: "place"`, a resource key and a one-sentence
   reason. The tool refuses a place without a reason, a resource that does not exist, or one that
   does not accept the file.
3. **`settled!`**, after the agent. A file that is still staged goes to default storage if that is
   a candidate, or else to the first candidate by key. With no candidates, the analysis fails and
   the file stays staged.

Each placement writes a `placement` step recording the resource, the path, `by` (`return`, `agent`
or `default`) and the reason, cut at 500 characters. If another feed already holds that path in the
chosen resource, the feed's id is added to the file name instead of overwriting the other file.
Once the reference is recorded, the staged copy is purged.

## Snapshots

A snapshot needs a `web` resource. That resource renders the page in headless Chrome, in an
incognito window. Ferrum's defaults turn off the same-origin policy and site isolation, and uris
turns both back on, because a compromised renderer that can read across origins is the risk. The
browser is also started with flags that block new windows, permission prompts, the file system,
notifications, speech and pings.

The address is checked once before the page loads. The browser can still resolve hosts again,
follow redirects and request anything the page asks for, so every request it makes is intercepted
as well. `data:` and `blob:` requests pass. `http` and `https` requests pass only if the address
check allows them. Every other scheme is aborted, so `file://` stays blocked even where private
fetches are allowed.

The window is 1280 pixels wide by default and can be set from 320 to 2560. A full-page capture is
cut at a height of 20,000 pixels, the PNG must be under 25 MB, and the whole render must finish
within 120 seconds. The PNG and the page's text are written under `snapshots/` in the storage the
web resource names, or in default storage. This skips staging, because a second visit would render
a different page. The reference is keyed by the URL without its fragment, and the feed takes the
page's title.

## Sync

`Resource#sync!` claims the resource, so only one sync runs for it at a time, and starts a `sync`
run. `ScheduleSyncsJob` does this every minute for each resource that is due. `SyncResourceJob`
walks the resource page by page, with checkpoints, so a sync interrupted by a deploy resumes from
the start of the page it was on. Every object it finds becomes a reference on a feed. That feed is
analyzed only if the reference has not been analyzed since it last changed, no pass for it is still
open, and none failed in the last day — a failure waits for the bytes to change or a day to pass,
so a file that breaks the analyzer is not retried on every sync. Synced records already live
somewhere, so they are never placed.

## Addresses

`fetchUrl`, `snapshotUrl` and every download or render request go through `PublicAddress`. It
accepts only `http` and `https` URLs. It resolves the host name and refuses the URL if any address
the name resolves to falls in a loopback, private, link-local, shared, documentation, multicast or
otherwise reserved range, for IPv4 or IPv6. It checks an IPv4-mapped IPv6 address as the IPv4
address it wraps. A host that does not resolve is refused. `URIS_ALLOW_PRIVATE_FETCH` lifts the
address ranges, but not the scheme rule.

A download, and every feed, WebDAV or search request a resource makes, resolves the host once,
checks every address it got, and connects to one of those addresses rather than handing the name
back to be looked up again — otherwise a resolver could answer a public address to the check and a
private one to the connection. The Host header and certificate still name the host, and each redirect
is resolved and checked afresh. The headless browser, the MCP client and git resolve for themselves.

Paths are cleaned by `Intake.key_for` before anything is stored. Backslashes become slashes, control
characters are removed, and empty, `.` and `..` segments are dropped. That leaves a relative key
that cannot climb out of wherever it is placed. Fetched names and note names go further: they are
reduced to a parameterized stem of at most 180 characters, plus an extension of at most 16.
